# HotelScout

HotelScout — учебное веб-приложение для сбора и анализа публично наблюдаемых цен гостиниц. Пользователь задаёт место, даты проживания и количество гостей, после чего приложение получает выдачу Google Hotels через SerpApi, приводит ответ к собственной структуре, сохраняет снимок в PostgreSQL и показывает результат в браузере.

Проект разрабатывается как основа системы мониторинга гостиничных цен. Текущая версия подтверждает работоспособность полного пути данных: от формы в браузере до внешнего API, базы данных, истории наблюдений и графика.

## Текущее состояние

HotelScout является работающим техническим прототипом, а не только макетом интерфейса. Он выполняет настоящие запросы к SerpApi, получает данные Google Hotels и сохраняет их в PostgreSQL.

Текущая версия подходит для демонстрации:

- получения актуальной гостиничной выдачи;
- серверной интеграции с внешним API;
- приведения внешнего JSON к внутренней модели;
- сохранения последовательных снимков цен;
- построения истории для выбранной гостиницы;
- разделения системы на веб-интерфейс, API и базу данных;
- запуска всех компонентов через Docker Compose.

Сейчас наблюдение запускается пользователем вручную. Автоматическое выполнение по расписанию и постоянный список наблюдаемых гостиниц ещё не реализованы.

## Продукт, практика и диплом

### Одна фраза о продукте

**HotelScout — веб-система для владельцев и управляющих гостиницами, которая регулярно собирает публичные цены конкурентов, сохраняет их историю и помогает анализировать изменения рынка.**

В этой формулировке:

- целевой пользователь — владелец, управляющий или сотрудник гостиницы;
- объект наблюдения — собственная гостиница и выбранные конкуренты;
- источник — публичные гостиничные предложения;
- основной результат — история, сравнение и аналитика, а не разовый поиск номера для туриста.

### Идея работы на практике

Практика должна подтвердить техническую реализуемость идеи и дать работающий минимальный продукт. Цель этапа — доказать, что система действительно может получать данные, приводить их к единому виду, сохранять последовательные наблюдения и показывать динамику пользователю.

Предлагаемый результат практики:

- работающий веб-интерфейс;
- интеграция хотя бы с одним реальным источником — SerpApi/Google Hotels;
- ручное создание снимка цен;
- PostgreSQL с историей запусков и предложений;
- выбор гостиницы и просмотр её истории;
- график цены для сопоставимых условий;
- базовая обработка ошибок;
- запуск проекта через Docker Compose;
- документация и воспроизводимая демонстрация.

Если времени и квоты достаточно, практику можно усилить:

- сохранением списка наблюдаемых гостиниц;
- простым расписанием автоматического сбора;
- сравнением двух или нескольких гостиниц;
- минимальным контролем расходования квоты.

Практика не обязана превращать систему в полностью готовый коммерческий сервис. Главное — законченный сквозной сценарий и подтверждение того, что на выбранном источнике можно строить дальнейшую работу.

### Идея дипломной работы

Дипломная работа может развить технический прототип в полноценную систему конкурентного мониторинга для гостиничного бизнеса. Основной акцент смещается с проверки API на автоматизацию, качество данных, аналитику и удобство регулярной работы.

Предлагаемый результат диплома:

- собственная гостиница и управляемый список конкурентов;
- постоянные конфигурации наблюдения: город, даты, гости, валюта и частота;
- автоматический сбор по расписанию;
- накопление длительной истории;
- графики и календарное представление;
- сравнение нескольких гостиниц;
- абсолютное и процентное изменение цены;
- минимальные, максимальные и средние значения за период;
- подробные предложения отдельных продавцов через Property Details, если источник их предоставляет;
- контроль квоты, повторные попытки и журнал ошибок;
- уведомления о существенном изменении цены;
- расширение числа источников или резервный парсер при обоснованной необходимости;
- экспорт результатов;
- подготовка к развёртыванию и регулярному использованию.

Дополнительная исследовательская часть диплома может включать поиск аномалий, оценку ценовой позиции гостиницы относительно конкурентов или прогнозирование. Эти функции следует добавлять только после накопления достаточной истории и проверки качества исходных данных.

### Главное отличие этапов

**Практика доказывает, что основной механизм получения и накопления данных работает; диплом превращает этот механизм в автоматизированный аналитический продукт для регулярного использования.**

| Практика | Диплом |
|---|---|
| Проверка реализуемости идеи | Полноценное развитие системы |

## Возможности

### Поиск гостиниц

Пользователь может указать:

- город, район, достопримечательность или название гостиницы;
- дату заезда;
- дату выезда;
- количество взрослых;
- количество детей.

В текущем интерфейсе используются российский регион выдачи, русский язык и цены в рублях. Эти значения присутствуют во внутреннем запросе и в дальнейшем могут быть вынесены в отдельные элементы формы.

### Получение внешних данных

Сервер обращается к SerpApi с движком `google_hotels`. Из ответа извлекаются:

- название гостиницы;
- идентификатор `property_token`, если он присутствует;
- тип и класс объекта, если они доступны в подходящем формате;
- рейтинг и количество отзывов;
- координаты;
- минимальная цена за ночь;
- цена до налогов и сборов, если она есть;
- общая цена;
- валюта;
- признак бесплатной отмены, если он есть;
- отдельные источники цен, если массив `prices` присутствует в ответе.

Полный ответ SerpApi дополнительно сохраняется в JSONB без потери исходных полей. Это позволяет позже изменить нормализацию и извлечь дополнительные данные из уже выполненных запросов.

### Сохранение снимков

Каждое нажатие «Найти гостиницы» создаёт новый запуск сбора. В базе сохраняются:

- условия поиска;
- время наблюдения;
- состояние запуска;
- технический идентификатор SerpApi;
- исходный ответ;
- все нормализованные предложения;
- ошибка, если получение данных завершилось неудачно.

### История цены

Для каждой найденной гостиницы доступна кнопка «Показать историю». Интерфейс показывает:

- число сохранённых наблюдений;
- минимальную цену;
- максимальную цену;
- график;
- дату, время, цену и номер каждого снимка.

Открытие истории не вызывает SerpApi и не расходует внешнюю квоту. Данные читаются из локальной PostgreSQL.

### Обработка ошибок

Приложение проверяет входные параметры, фиксирует ошибки внешнего источника и не оставляет запуск в неопределённом состоянии. Например, отсутствие ключа SerpApi приводит к понятному ответу API и записи запуска со статусом `error`.

## Ограничения

Границы текущей версии важно учитывать при интерпретации результатов.

### Нет автоматического мониторинга

История уже поддерживается, но снимки создаются только при ручном поиске. Планировщик, который выполнял бы сбор каждый день или несколько раз в день, ещё не добавлен.

### Нет постоянного списка наблюдаемых гостиниц

Кнопка «Показать историю» выбирает гостиницу для просмотра, но не добавляет её в постоянное наблюдение. В базе пока отсутствует сущность «наблюдаемый объект» с собственным расписанием.

### Загруженность гостиницы неизвестна

Google Hotels и SerpApi возвращают публичные предложения и цены, но не внутреннюю загрузку гостиницы, число занятых номеров или процент occupancy. Наличие цены показывает наблюдаемое предложение, но не позволяет вычислить фактическую загрузку объекта.

### Цены не являются внутренними тарифами гостиницы

Технически приложение получает публично доступные предложения Google Hotels. Они могут использоваться для B2B-мониторинга конкурентной среды, но не являются закрытыми договорными B2B-тарифами гостиниц или данными внутренней PMS.

### Разбивка по продавцам доступна не всегда

В общей выдаче поле `prices` может отсутствовать. В таком случае система знает минимальную наблюдаемую цену гостиницы, но не знает, каким продавцом она была предложена. Для подробной разбивки требуется отдельный запрос Property Details по `property_token`; этот сценарий пока не реализован и потребляет дополнительную квоту SerpApi.

### Нет пагинации

Сейчас сохраняется массив `properties` из одной страницы ответа. Токен следующей страницы не используется, поэтому результат не следует считать полным списком всех гостиниц города.

### Нет прогнозирования и уведомлений

Приложение пока не прогнозирует будущие цены, не определяет аномалии и не отправляет уведомления об изменениях.

### Нет пользовательских аккаунтов

В текущей версии отсутствуют регистрация, авторизация, роли и разделение данных между пользователями.

### Локальный режим

Docker-конфигурация предназначена для разработки и демонстрации на локальном компьютере. В ней нет HTTPS, reverse proxy, резервного копирования и других механизмов промышленного развёртывания.

### Зависимость от внешнего сервиса

Результат зависит от SerpApi и Google Hotels: их доступности, квот, формата ответа и правил использования. Изменение внешней структуры JSON может потребовать обновления адаптера.

## Архитектура

Система разделена на три компонента:

```text
┌─────────────────────┐
│  Vue 3 + Vite       │
│  веб-интерфейс      │
│  localhost:5173     │
└──────────┬──────────┘
           │ HTTP
           ▼
┌─────────────────────┐       HTTPS       ┌─────────────────────┐
│  Fastify + Node.js  │ ─────────────────▶│  SerpApi             │
│  API приложения     │                   │  Google Hotels       │
│  localhost:3000     │◀───────────────── │  JSON                │
└──────────┬──────────┘                    └─────────────────────┘
           │ SQL
           ▼
┌─────────────────────┐
│  PostgreSQL         │
│  снимки и история   │
└─────────────────────┘
```

Браузер не обращается к SerpApi или PostgreSQL напрямую. Все внешние запросы и операции с данными выполняет Fastify API.

Такое разделение позволяет:

- не передавать API-ключ в браузер;
- централизованно проверять входные данные;
- изолировать формат внешнего источника;
- сохранять единый формат гостиничного предложения;
- заменить или добавить источник без полной переделки интерфейса;
- позднее подключить планировщик к той же серверной логике.

## Как проходит поиск

1. Пользователь заполняет форму Vue и нажимает «Найти гостиницы».
2. Браузер отправляет JSON в `POST /api/hotels/search`.
3. Fastify проверяет схему тела запроса и порядок дат.
4. В `collection_runs` создаётся запись со статусом `running`.
5. Сервер формирует запрос SerpApi и добавляет ключ из переменной окружения.
6. SerpApi возвращает JSON Google Hotels.
7. Адаптер проверяет базовую структуру ответа и преобразует `properties` во внутренние объекты `HotelOffer`.
8. В одной транзакции запуск получает статус `success`, сохраняется исходный JSON и добавляются строки `hotel_offers`.
9. Fastify возвращает браузеру номер снимка и массив предложений.
10. Vue отображает карточки гостиниц.

Если внешний запрос завершается ошибкой, запуск получает статус `error`, а текст ошибки сохраняется в `error_message`.

## Почему работают разные поисковые фразы

Поле города является свободной поисковой строкой. Сервер не пытается сам распознать слово «Москва» и не ищет его в локальном справочнике. Значение передаётся SerpApi как параметр `q`.

Поэтому допустимы, например:

```text
Москва
Новосибирск
Hotels in Novosibirsk, Russia
Отели рядом с Красной площадью
Cosmos Novosibirsk Hotel
```

Google Hotels самостоятельно интерпретирует город, район, объект или название гостиницы. Поскольку используется движок `google_hotels`, для поиска по городу достаточно строки `Москва`; слова «отели» или `Hotels in` не обязательны.

Формулировка всё же может влиять на релевантность и состав выдачи. Запрос по точному названию гостиницы также может привести к результату иного типа, чем общий поиск по городу.

Пример параметров внешнего запроса без секретного ключа:

```text
engine=google_hotels
q=Москва
check_in_date=2026-10-20
check_out_date=2026-10-21
adults=2
children=0
currency=RUB
gl=ru
hl=ru
```

## Технологии

### Сервер

- **Node.js 22** — среда выполнения JavaScript и TypeScript.
- **TypeScript** — статическая проверка типов.
- **Fastify 5** — HTTP-сервер, маршрутизация и проверка схем запросов.
- **Встроенный `fetch`** — запросы к SerpApi без дополнительного HTTP-клиента.
- **`pg`** — прямое подключение к PostgreSQL.
- **SQL-миграции** — явное версионирование структуры базы.

ORM в текущей версии не используется. Запросы написаны на параметризованном SQL, поэтому структура данных остаётся видимой и не зависит от дополнительного слоя абстракции.

### Интерфейс

- **Vue 3** — реактивный веб-интерфейс.
- **Vite 6** — dev-сервер и production-сборка.
- **TypeScript** — типы запросов, ответов и данных интерфейса.
- **SVG** — график цены без отдельной библиотеки визуализации.

### Инфраструктура

- **PostgreSQL 17** — хранение снимков, предложений и исходного JSON.
- **Docker Compose** — совместный запуск базы, API и интерфейса.

## Подготовка и запуск

### Требования

Для обычного запуска требуется:

- установленный и запущенный Docker Desktop;
- доступ к интернету для SerpApi;
- действующий ключ SerpApi.

Локальная установка Node.js и PostgreSQL для Docker-сценария не нужна.

### Переменные окружения

Создайте `.env` из примера:

```powershell
Copy-Item .env.example .env
```

Содержимое `.env`:

```dotenv
SERPAPI_API_KEY=ваш_ключ
POSTGRES_DB=hotelscout
POSTGRES_USER=hotelscout
```

## HTTP API приложения

### `GET /health`

Проверяет работу Fastify и соединение с PostgreSQL.

```json
{
  "status": "ok",
  "database": "connected"
}
```

### `POST /api/hotels/search`

Запускает новый сбор данных через SerpApi и сохраняет снимок.

Пример тела:

```json
{
  "query": "Москва",
  "checkIn": "2026-10-20",
  "checkOut": "2026-10-21",
  "adults": 2,
  "children": 0,
  "currency": "RUB",
  "country": "ru",
  "language": "ru"
}
```

Ограничения входных данных:

- `query`: от 2 до 200 символов;
- `checkIn`, `checkOut`: даты `YYYY-MM-DD`;
- выезд должен быть позже заезда;
- `adults`: от 1 до 6;
- `children`: от 0 до 4;
- `currency`: три заглавные латинские буквы;
- `country`: двухбуквенный код в нижнем регистре;
- `language`: строка длиной от 2 до 10 символов;
- неизвестные поля отклоняются.

Упрощённый пример ответа:

```json
{
  "runId": 10,
  "offers": [
    {
      "propertyToken": "...",
      "name": "Название гостиницы",
      "propertyType": "hotel",
      "hotelClass": null,
      "rating": 4.6,
      "reviews": 1765,
      "latitude": 55.0,
      "longitude": 82.0,
      "nightlyPrice": 4385,
      "nightlyPriceBeforeTaxes": 4385,
      "totalPrice": 4385,
      "currency": "RUB",
      "available": true,
      "freeCancellation": null,
      "sourcePrices": []
    }
  ]
}
```

`sourcePrices: []` не означает отсутствие цены. Это означает, что общая выдача не предоставила разбивку по продавцам; минимальная цена при этом находится в `nightlyPrice`.

Возможные ошибки:

- `400` — некорректные параметры или порядок дат;
- `502` — ошибка ответа или соединения с SerpApi;
- `503` — ключ SerpApi не настроен;
- `500` — внутренняя ошибка приложения.

### `GET /api/hotels/history`

Возвращает сохранённые наблюдения одной гостиницы для одинаковых условий.

| Параметр | Обязателен | Назначение |
|---|---:|---|
| `propertyToken` | нет | идентификатор Google Hotels; используется при наличии |
| `name` | да | название гостиницы и резервный идентификатор |
| `checkIn` | да | дата заезда |
| `checkOut` | да | дата выезда |
| `adults` | да | количество взрослых |
| `children` | да | количество детей |
| `currency` | да | валюта |

Пример ответа:

```json
{
  "hotel": {
    "propertyToken": "...",
    "name": "Cosmos Novosibirsk Hotel"
  },
  "points": [
    {
      "runId": 6,
      "observedAt": "2026-10-09T12:50:00.000Z",
      "nightlyPrice": 4385,
      "totalPrice": 4385,
      "currency": "RUB"
    }
  ]
}
```

## Хранение данных

### `schema_migrations`

Служебная таблица со списком уже применённых SQL-файлов. Она не даёт одной миграции выполниться повторно.

### `collection_runs`

Одна строка соответствует одной попытке получить снимок.

| Поле | Значение |
|---|---|
| `id` | внутренний номер снимка |
| `observed_at` | время наблюдения на сервере |
| `query` | исходная поисковая строка |
| `check_in`, `check_out` | даты проживания |
| `adults`, `children` | состав гостей |
| `currency`, `country`, `language` | параметры локализации |
| `status` | `running`, `success` или `error` |
| `serpapi_search_id` | идентификатор поиска SerpApi |
| `error_message` | причина неудачи |
| `raw_response` | полный исходный JSONB |

### `hotel_offers`

Каждая строка является предложением гостиницы в конкретном снимке.

| Поле | Значение |
|---|---|
| `run_id` | связь с `collection_runs` |
| `property_token` | идентификатор объекта Google Hotels |
| `name`, `property_type`, `hotel_class` | описание объекта |
| `rating`, `reviews` | пользовательская оценка |
| `latitude`, `longitude` | координаты |
| `nightly_price` | минимальная цена за ночь |
| `nightly_price_before_taxes` | цена до налогов и сборов |
| `total_price` | общая цена за выбранный период |
| `currency` | валюта |
| `available` | удалось ли наблюдать цену |
| `free_cancellation` | признак бесплатной отмены, если доступен |
| `source_prices` | JSONB с ценами отдельных источников |

Связь имеет вид:

```text
collection_runs (1) ──────── (много) hotel_offers
```

Удаление запуска каскадно удаляет связанные предложения.

## История цен

История строится по времени `collection_runs.observed_at`. Для выбора гостиницы предпочтительно используется `property_token`; если его нет, используется точное название.

Чтобы точки графика были сопоставимы, SQL-запрос дополнительно требует совпадения:

- даты заезда;
- даты выезда;
- количества взрослых;
- количества детей;
- валюты.

Это означает, что поиск той же гостиницы на другие даты образует другой ряд наблюдений. Такие цены нельзя автоматически считать изменением одной и той же услуги.

`observed_at` — время, когда система увидела предложение. `check_in` и `check_out` — период будущего проживания. Эти понятия не следует смешивать.

Сейчас график строится непосредственно во Vue с помощью SVG. Специальная библиотека графиков не используется.

## Миграции базы

При каждом запуске API до открытия HTTP-порта выполняется `runMigrations`:

1. API подключается к PostgreSQL.
2. Получает advisory lock, чтобы два процесса не применяли миграции одновременно.
3. Создаёт `schema_migrations`, если её нет.
4. Читает файлы `api/migrations/*.sql` по имени.
5. Пропускает уже применённые файлы.
6. Выполняет каждую новую миграцию в транзакции.
7. Записывает имя успешно применённого файла.

Для новой миграции следует создать следующий SQL-файл, например:

```text
api/migrations/002_monitored_hotels.sql
```

Уже применённую миграцию лучше не переписывать: изменение структуры оформляется новым файлом.

## Безопасность

- `.env` исключён из Git.
- Ключ SerpApi передаётся только контейнеру `api`.
- Vue не получает и не хранит ключ.
- Значение ключа не должно попадать в сообщения об ошибках и логи.
- SQL-запросы используют параметры `$1`, `$2` и так далее, а не склейку строк.
- PostgreSQL не публикует порт на хост и доступна только внутри Docker-сети.
- CORS в локальной конфигурации разрешает интерфейс с `http://localhost:5173`.

Текущий пароль PostgreSQL предназначен только для локальной разработки. Для развёртывания необходимо использовать отдельные секреты и не хранить их в репозитории.

## Диагностика проблем

### Docker Desktop не запущен

Признаки: команды сообщают, что не удаётся подключиться к Docker Engine или найти named pipe. Запустите Docker Desktop, дождитесь готовности и повторите `docker compose up -d`.

### Интерфейс не открывается

```powershell
docker compose ps
docker compose logs --tail 100 web
```

Порт `5173` не должен быть занят другим приложением.

### API не отвечает

```powershell
docker compose logs --tail 100 api
```

Также откройте <http://localhost:3000/health>.

### `SERPAPI_API_KEY is not configured`

Убедитесь, что:

1. существует файл `.env` рядом с `compose.yaml`;
2. строка `SERPAPI_API_KEY=...` не пустая;
3. после изменения `.env` API был пересоздан:

```powershell
docker compose up -d --force-recreate api
```

### SerpApi возвращает ошибку

Возможные причины:

- закончилась квота;
- ключ неверен;
- нет доступа к интернету;
- внешняя служба временно недоступна;
- Google Hotels не вернул ожидаемый массив `properties`;
- точный запрос привёл к другой форме ответа.

Сообщение сохраняется в `collection_runs.error_message` и выводится в лог API.

### История пустая

Убедитесь, что ранее выполнялся поиск той же гостиницы на те же даты, с тем же количеством взрослых и детей и в той же валюте.

### Изменения кода не появились в браузере

В dev-режиме каталоги подключены к контейнерам как volumes, но файловое наблюдение Docker Desktop на Windows иногда срабатывает не сразу. Перезапустите нужный сервис:

```powershell
docker compose restart web
docker compose restart api
```

## Краткое описание для демонстрации

HotelScout построен как клиент-серверное приложение. Vue отвечает за интерфейс, Fastify — за проверку запросов, бизнес-логику и работу с внешним источником, PostgreSQL — за хранение снимков. Пользователь задаёт место и условия проживания, после чего сервер получает выдачу Google Hotels через SerpApi, нормализует её и сохраняет. Повторные снимки формируют историю цены для одинаковых условий. На текущем этапе сбор запускается вручную; следующий этап — постоянный список наблюдаемых гостиниц и автоматическое выполнение по расписанию.
